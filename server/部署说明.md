# PCL3 更新与公告服务端 · 部署说明

## 一、你的服务器信息

| 项目 | 值 |
|---|---|
| 网站 | `https://pcl3.byethost9.com` |
| FTP 主机 | `ftp.byethost9.com` |
| FTP 用户名 | `YOUR_DB_USER` |
| FTP 密码 | `YOUR_DB_PASSWORD` |
| MySQL 主机 | `YOUR_DB_HOST` |

> **MySQL 用不上**：实测 `YOUR_DB_HOST:3306` 从外部不可达，
> 这是 Byethost 免费主机的限制（数据库只能在主机内部用 PHP 访问）。
> 所以本方案改用 **PHP + JSON 文件**，不依赖数据库，部署更简单。

---

## 二、重要：Byethost 有 JS 挑战

实测该主机对每个访客返回一个 AES Cookie 挑战页：

```html
<script src="/aes.js"></script>
<script>
var a=toNumbers("...key..."), b=toNumbers("...iv..."), c=toNumbers("...cipher...");
document.cookie = "__test=" + toHex(slowAES.decrypt(c, 2, a, b));
location.href = "...?i=1";
</script>
```

普通 HTTP 客户端会被挡在门外。

**已在 PCL3 客户端里实现绕过**（`Modules\ModByethost.vb`）：
解析三个参数 → 用标准 AES-128-CBC 解密 → 算出 `__test` cookie → 带上重试。

实测结果：

```
IsChallengePage => True
SolveChallenge  => 7ec6f6c47dbd4baa87ce80d21c4b07c7
带该 cookie 访问站点根 => HTTP 200，挑战已通过
```

## 三、部署步骤

### 1. 上传 PHP 接口

用 FTP 工具（FileZilla / WinSCP）连接 `ftp.byethost9.com`，
把 `api` 文件夹整个上传到网站根目录（通常是 `htdocs`）。

上传后目录结构应为：

```
htdocs/
└── api/
    └── index.php
```

### 2. 修改管理令牌

编辑 `index.php` 第 24 行：

```php
const ADMIN_TOKEN = 'CHANGE_ME_TO_A_LONG_RANDOM_STRING';
```

改成一串足够长的随机字符（建议 32 位以上），例如：

```php
const ADMIN_TOKEN = 'pcl3_a7f3d9e1c4b8_2f6a5d0e9b3c7a1f';
```

**这个 token 是发布权限的唯一凭据，不要泄露。**

### 3. 创建数据目录

在 `api` 同级或 `api` 内创建 `data` 文件夹，权限设为 755：

```
htdocs/api/data/
```

接口首次写入时会自动创建，但建议手动建好并确认可写。

### 4. 验证部署

浏览器打开：

```
https://pcl3.byethost9.com/api/?action=check&version=3001&channel=release
```

应返回：

```json
{
    "ok": true,
    "hasUpdate": false,
    "current": 3001,
    "latest": null,
    "notices": [],
    "serverTime": 1793...
}
```

## 四、接口文档

| 方法 | 地址 | 说明 |
|---|---|---|
| GET | `?action=check&version=3001&channel=release` | 检查更新 + 拉公告 |
| GET | `?action=latest` | 最新版本 |
| GET | `?action=notices` | 公告列表 |
| POST | `?action=publish` | 发布版本（需 token） |
| POST | `?action=notice` | 发布公告（需 token） |
| POST | `?action=delete_notice` | 删除公告（需 token） |

### publish 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `token` | 是 | 管理令牌 |
| `version` | 是 | 如 `3.0.0.2` |
| `url` | 是 | 下载直链 |
| `sha256` | 否 | 文件校验值 |
| `size` | 否 | 字节数 |
| `channel` | 否 | `release` / `beta`，默认 `release` |
| `notes` | 否 | 更新说明 |
| `force` | 否 | `1` 表示强制更新 |

### notice 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `token` | 是 | 管理令牌 |
| `title` | 是 | 公告标题 |
| `content` | 否 | 公告内容 |
| `priority` | 否 | 越大越靠前，默认 0 |
| `expire` | 否 | 过期 Unix 时间戳，0 为永久 |
| `id` | 否 | 指定则覆盖同 ID 公告 |

## 五、推送工具

`推送工具.ps1` 是给你用的管理界面。

### 首次配置

用记事本打开，改这两行：

```powershell
$ApiBase = "https://pcl3.byethost9.com/api/"
$Token   = "你刚才在 index.php 里设置的 ADMIN_TOKEN"
```

### 使用

右键 → **使用 PowerShell 运行**，或：

```powershell
powershell -ExecutionPolicy Bypass -File 推送工具.ps1
```

菜单：

```
[1] 发布新版本
[2] 发布公告
[3] 查看当前版本
[4] 查看全部公告
[5] 删除公告
[6] 测试连接
[0] 退出
```

## 六、发布一个新版本的完整流程

1. 编译出新的 `Plain Craft Launcher 3.exe`
2. 算 SHA-256：
   ```powershell
   (Get-FileHash "Plain Craft Launcher 3.exe" -Algorithm SHA256).Hash
   ```
3. 把 exe 传到能直链下载的地方（你的主机 `htdocs/download/` 或网盘直链）
4. 运行 `推送工具.ps1` → 选 `[1] 发布新版本`
5. 填版本号 `3.0.0.2`、下载地址、SHA-256、更新说明
6. 客户端下次启动或点「检查更新」时就会看到

## 七、注意事项

1. **HTTPS 证书**：你说过一段时间会签发。目前实测 `https://` 已可用，
   如果中间出现证书错误，客户端会记录警告但不阻塞启动。
2. **Cookie 有效期 6 小时**：客户端缓存 4 小时，过期会自动重新解挑战。
3. **Byethost 可能改算法**：如果某天更新检查突然全部失败，
   先浏览器打开接口看挑战页是否变了。变了就告诉我，我调整解析规则。
4. **免费主机有流量与并发限制**：公告接口建议客户端只在启动时调一次，
   不要高频轮询。
5. **数据备份**：`api/data/*.json` 就是全部数据，定期下载备份即可。

---

## 八、安全提醒

- `ADMIN_TOKEN` 一旦泄露，任何人都能往你的更新源推假版本，
  **这是供应链攻击的入口**，务必保管好。
- 建议发布时都填 `sha256`，客户端可校验下载文件完整性。
- FTP 密码是明文传输，尽量在可信网络下操作，用完可考虑改密码。
